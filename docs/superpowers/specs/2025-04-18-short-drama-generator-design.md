## 1. 项目概述

### 1.1 产品定位

面向内容创作者的**企业级本地部署平台**，将长篇小说自动转化为可发布的短视频剧集。系统采用分阶段确认流程，确保每集内容质量可控。

### 1.2 核心价值主张

- **角色一致性**: AI 生成角色形象，固定种子确保跨集一致性
- **端到端生成**: 从 TXT 小说到完整视频（含配音、字幕）
- **质量可控**: 分阶段审核，用户参与关键决策
- **成本透明**: 按需付费，精确到资源消耗

### 1.3 目标用户画像

**内容创作者/工作室**
- 需要批量生产短剧内容
- 有技术团队或外包资源
- 注重成本控制和内容质量
- 偏好本地部署保障数据安全

## 3. 核心功能模块

### 3.1 小说上传与解析模块

**功能描述**
- 支持 TXT 格式小说上传
- 自动识别章节结构（基于正则和 NLP）
- 提取角色信息、场景信息
- 生成章节大纲

**技术实现**
```
章节识别策略:
1. 正则匹配：第[一二三四五...]章 / Chapter \d+ / CHAPTER \d+
2. 语义分析：基于文本相似度检测章节边界
3. 用户确认：展示章节划分，支持手动调整
```

**输出产物**
- 章节列表（标题、起始位置、预估时长）
- 角色列表（名称、出场章节、描述）
- 场景列表（地点、时代背景）

### 3.2 角色管理模块

**功能描述**
- AI 根据小说描述生成角色形象
- 固定种子确保跨集一致性
- 角色库管理（增删改查）

**技术实现**
```
角色生成流程:
1. 提取角色描述（外貌、年龄、性格）
2. 构建 Prompt：
   "A digital portrait of [character], [description], 
    consistent character design, high quality, 8k"
3. 生成 4 张候选图供用户选择
4. 保存种子值和最终图片
```

**数据结构**
```json
{
  "character_id": "uuid",
  "name": "林黛玉",
  "description": "年约十六七岁，体态纤弱，眉尖若蹙",
  "seed": 123456789,
  "image_url": "/storage/characters/lin_daiyu.png",
  "voice_config": {
    "voice_id": "elevenlabs_voice_xxx",
    "speed": 1.0,
    "pitch": 0
  },
  "style_prompt": "elegant, frail, traditional chinese beauty"
}
```

### 3.3 剧本生成模块

**功能描述**
- 将小说章节转化为短剧剧本格式
- 提取对白、动作、场景描述
- 适配短剧节奏（3-5 分钟/集）

**剧本格式**
```yaml
episode: 1
title: "初进荣国府"
duration: "4:30"
scenes:
  - scene_id: 1
    location: "荣国府大门"
    characters: ["林黛玉", "贾母", "王熙凤"]
    actions:
      - character: "林黛玉"
        action: "从轿中走下，环顾四周"
        emotion: "紧张、好奇"
    dialogues:
      - character: "王熙凤"
        text: "这位妹妹我曾见过的"
        emotion: "热情、夸张"
    camera: "中景到特写"
```

### 3.4 场景生成模块

**功能描述**
- 根据剧本场景描述生成背景图
- 支持室内、室外、古代、现代等多种场景
- 保持场景风格一致性

**场景分类**
| 类型 | 子类型 | 示例 |
|------|--------|------|
| 古代室内 | 宫殿、客栈、书房、闺房 | 紫禁城大殿、江南园林 |
| 古代室外 | 街道、山林、河边、战场 | 长安街市、塞外风光 |
| 现代室内 | 办公室、咖啡厅、公寓 | 总裁办公室、咖啡厅 |
| 现代室外 | 街道、公园、商场 | 都市夜景、校园 |

### 3.5 配音合成模块

**功能描述**
- 为每个角色分配专属音色
- 支持情感标记（开心、愤怒、悲伤、惊讶）
- 生成同步字幕文件

**情感标签映射**
| 情感 | 描述 | 应用示例 |
|------|------|----------|
| neutral | 平静 | 旁白、日常对话 |
| happy | 开心 | 重逢、好消息 |
| sad | 悲伤 | 离别、失败 |
| angry | 愤怒 | 争吵、复仇 |
| surprised | 惊讶 | 意外、揭露真相 |
| fearful | 恐惧 | 危险、威胁 |

### 3.6 视频合成模块

**功能描述**
- 数字人渲染（角色形象 + 配音口型同步）
- 场景合成
- 字幕叠加
- 转场效果

### 3.7 分阶段审核工作流

**阶段 1：章节确认**
- 展示自动识别的章节列表
- 支持合并、拆分、重命名
- 用户确认后进入下一阶段

**阶段 2：角色设定**
- 展示提取的角色列表
- 为每个角色生成/选择形象
- 配置声音参数

**阶段 3：剧本审核**
- 逐集展示生成剧本
- 提供富文本编辑器修改
- 支持重新生成单集

**阶段 4：预览生成**
- 生成第一集完整视频预览
- 用户确认风格无误后批量生成

**阶段 5：批量生成**
- 后台批量处理剩余集数
- 实时进度显示
- 支持暂停/恢复

## 4. 数据模型

### 4.1 核心实体关系

```
+-------------+       +-------------+       +-------------+
|    User     |-------|   Project   |-------|   Novel     |
|  (用户)      |  1:N  |   (项目)     |  1:1  |   (小说)     |
+-------------+       +-------------+       +-------------+
                              |
                              | 1:N
                              v
                       +-------------+       +-------------+
                       |  Episode    |-------|   Script    |
                       |   (剧集)     |  1:1  |   (剧本)     |
                       +-------------+       +-------------+
                              |
                              | N:M
                              v
                       +-------------+
                       |  Character  |
                       |   (角色)     |
                       +-------------+
```

### 4.2 关键表结构

**projects 表**
```sql
CREATE TABLE projects (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    name VARCHAR(255),
    status ENUM('draft', 'parsing', 'character_design', 'script_review', 'preview', 'generating', 'completed'),
    novel_id UUID REFERENCES novels(id),
    config JSONB,
    cost_estimate DECIMAL(10,2),
    total_cost DECIMAL(10,2),
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);
```

**episodes 表**
```sql
CREATE TABLE episodes (
    id UUID PRIMARY KEY,
    project_id UUID REFERENCES projects(id),
    episode_number INT,
    title VARCHAR(255),
    source_chapters INT[],
    status ENUM('pending', 'script_generated', 'script_approved', 'generating', 'completed', 'failed'),
    script_content JSONB,
    video_url VARCHAR(500),
    duration INT,
    cost DECIMAL(10,2),
    generated_at TIMESTAMP
);
```

## 6. 技术难点与解决方案

### 6.1 角色一致性

**难点**: 同一角色在不同场景、角度、表情下保持一致

**解决方案**:
1. 使用固定种子 + LoRA 微调
2. 生成多角度参考图（正面、侧面、45度）
3. 角色图作为 ControlNet 参考
4. 建立角色特征向量库

### 6.2 口型同步

**难点**: 配音与数字人口型匹配

**解决方案**:
1. 使用 Wav2Lip 或类似技术
2. 预录制口型动画库
3. 音素分析驱动口型
4. 后期手动调整关键帧

### 6.3 GPU 资源管理

**难点**: AI 生成任务 GPU 密集型，资源调度复杂

**解决方案**:
1. 任务队列 + 优先级调度
2. GPU 虚拟化（NVIDIA MPS）
3. 夜间批量处理低优先级任务
4. 支持横向扩展 GPU 节点

## 9. 已确认事项

| 问题 | 决策 |
|------|------|
| **数字人渲染方案** | 开源方案 - SadTalker |
| **最大单集时长** | 7 分钟 |
| **并发要求** | 最多 5 个并发项目（5 用户或单用户 5 部短剧）|
| **历史数据处理** | 支持剧集修改和重新生成 |
| **导出格式** | 仅 MP4 |

### 9.1 SadTalker 技术规格

**开源数字人方案选型**
```
技术栈: SadTalker (https://github.com/OpenTalker/SadTalker)
输入: 静态角色图 + 音频文件
输出: 带口型同步的数字人视频
GPU 需求: 8GB+ VRAM (RTX 3070/4060 及以上)
生成速度: 约 1:2 (1 分钟视频需 2 分钟生成)
```

**替代方案备选**
- Wav2Lip: 更快的生成速度，但口型精度稍低
- GeneFace++: 支持全身动画，但配置更复杂

### 9.2 并发与资源规划

**并发场景分析**
```
场景: 5 个项目同时生成
每个项目: 假设 50 集，每集约 4 分钟视频

GPU 需求计算:
- 单集渲染时间: 约 8 分钟 (SadTalker 1:2 + 场景合成 1:1)
- 单项目总时长: 50 集 × 8 分钟 = 400 分钟 = 6.7 小时
- 5 项目并发: 需 5 个 GPU 实例 或 1 个 GPU + 队列调度

推荐配置:
- 开发环境: 1 × RTX 4090 24G
- 生产环境: 2 × A100 80G (支持 MIG 虚拟化)
```

### 9.3 历史数据管理策略

**重新生成机制**
```
版本控制:
- 每次生成创建新版本 (v1, v2, v3...)
- 保留历史版本 30 天
- 支持回滚到任意版本

增量更新:
- 修改剧本仅重新生成受影响片段
- 更换角色形象可选择性重渲染
- 场景调整支持单场景重生成
```
